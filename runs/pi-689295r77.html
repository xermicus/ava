Chess-VM Run Analysis

Task

The task asked for bot.cvm, a one-ply move-scoring policy in the CVM assembly language, rated by playing 20 games against each of 27 fixed-strength opponents (field ranges 0 to 1201 in this build). points() is derived only from the passing verdict's rating, and the game is explicitly a "loop task": keep improving and push again after the first passing submission.

What the agent did

Loop iteration 1 (turn 0). After reading README.md, task.md and SPEC.md, the agent wrote a first bot.cvm: a linear combination of MATEIN1 (mate-in-one, weighted at 1,000,000 to dominate all other terms), MATERIAL, SEE, HANGS, MOBILITY/OPPMOB, GIVESCHECK, CENTER, ISPROMO, ISCASTLE, EXPOSED, ENEMYKINGDIST, OWNKINGDIST. Before ever pushing, it ran this and dozens of variants through tar -c --exclude=.git . | curl -s --data-binary @- http://score:8080, the CI-without-pushing endpoint the README calls out as free and unrecorded. The agent.log shows well over 700 distinct rating readings from this endpoint, sweeping single weights (for ck in 80 100 120; do ..., for w in 4 5 6; do ..., etc.) across dozens of parameters, climbing from an early baseline around 702 up through the 900s and into the 1000s.

Only once a candidate beat the currently pushed best did the agent commit and git push origin task:

  • 12898fd "Chess move scoring policy rating ~1000" → attempt at 1658s, passed, rating 1000.04.
  • acad769 "Add capture bonus, rating ~1015" → attempt at 2047s, passed, rating 1015.25.
  • 622f4dd "Center weight 18, rating ~1017" → attempt at 2491s, passed, rating 1016.80.

All three real pushes passed and each improved on the last — no failed or wasted push appears in score.log.

Loop iteration 2. The agent resumed, confirmed origin/task was at 622f4dd (1017), and kept searching: it explicitly listed which CVM instructions it had and had not used (ATTACKERS/DEFENDERS, PIECEAT unused; SAFE, KINGDIST had hurt), tried an ISCAPTURE bonus and several combinations (e.g. combo center18, combo castle700, combo mob10 check90 — one such probe script exited 1, a harmless shell mistake, not a scoring failure), and ran a 40-combination randomized local search over the weight vector. Nothing beat 1017, and the agent explicitly recorded this as a plateau ("I'm at 1017 rating. Let me continue beyond my local neighborhood").

Loop iteration 3. More of the same weight-neighborhood search; this iteration was cut off mid-turn when the run's clock ran out (monitor.json shows "turn":4,"last_call":true, and the run metrics show one aborted request), so it never reached a natural agent_end.

Final (last-call) turn. The harness sent "Time is up. This is your final turn. Submit right now." The agent checked git status and git log (clean, 622f4dd both locally and on origin/task) and re-ran git push origin task, which correctly reported "Everything up-to-date" — nothing was lost, nothing needed to be redone.

Why it passed

Every real push was pre-validated against the same scoring logic the verifier uses, via the free score:8080 CI path, so there was no gap between what the agent believed would pass and what actually got pushed. The first passing entry was banked at 1658s, under half the 3600s budget, so even a subsequent stall or crash could not have produced a never_wrote or unbanked outcome.

Where it fell short

Once the 13-feature linear model plateaued at 1017 (about 85% of the way to the strongest, 4-ply-search opponent's 1201 rating), the agent's response was to keep perturbing the same weight vector rather than reconsidering the model's structure — for example combining features conditionally (opening vs. endgame), trying unused instructions like ATTACKERS/DEFENDERS/PIECEAT more seriously, or using some of the 20-million-cycle budget for a small amount of extra evaluation depth within the single decision (still legal since only .search is banned, not extra per-move computation). Roughly two-thirds of the total run time went into this unproductive fine-tuning after the score had already saturated, though because the plateau was correctly detected and nothing broken was ever pushed, this cost opportunity rather than the outcome.
