Task

The game is chess-vm: write bot.cvm, a one-ply move-scoring policy in a small register assembly language (CVM), with no lookahead (.search is rejected) and hard limits (256 instructions, 1024 data words, 20M cycles/decision). The engine calls the program once per legal move and plays the highest-scoring one; a fault or budget overrun anywhere in the 20 games x 27 opponents forces a first-legal-move fallback and fails the push regardless of rating. Every push to the task branch is graded; the unrecorded tar | curl http://score:8080 endpoint runs the identical pipeline for free, off the record.

Why the pushes passed

Every graded push had already been validated at the identical rating (modulo scorer randomness, which was minimal: e.g. the unrecorded run before the 1163 push read exactly 1162.58, matching the recorded 1162.58) against the unrecorded scorer before it was copied into the workspace and pushed. Because the CVM has strict fault rules (out-of-range LD, jumping outside code, running off the end, cycle overrun), and the agent grew the template incrementally while continuously re-testing it against the real scorer rather than reasoning abstractly about cycle counts, it never introduced a fault: the per-move cost of the hanging/threat loop (64 iterations x a few chess instructions, dominated by MOBILITY/OPPMOB at 200 cycles and SEE at 128) stayed safely inside the 20M-cycle budget, and no push ever came back with a fault or a lower rating than what local testing predicted.

Assessment

This is a clean, well-instrumented run. The single most consequential decision was recognizing that the CI-without-pushing endpoint (http://score:8080) is a full, free, unrecorded copy of the grading pipeline, and building a Python templating + search harness around it early (right after the first, mediocre push). That converted "tune the eval function" from a slow loop of graded pushes into an essentially unlimited local search (855 total proxy requests, almost all against score, against just 6 recorded git pushes), so every graded push was a known-good improvement. Backgrounding the multi-minute climbing jobs (climb.py & equivalent via the task tool, sleep-then-poll) let the agent keep working without stalling on wall-clock. The agent also correctly recognized diminishing returns (going from 1224 to 1258, above the field's ceiling) and released voluntarily well under the time budget rather than grinding for marginal gains or (worse) risking a last-second unbanked push -- there was no unbanked or wasted-until-last-call behavior at all; the first pass was banked in the first 5 minutes and every subsequent push improved on the last.
