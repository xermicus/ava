Task and constraints

The task was chess-vm: submit bot.cvm, a one-ply move-scoring program in the CVM assembly language (SPEC.md), evaluated by playing 20 games against each of 27 opponents. There is no search, no memory beyond 16 registers and a read-only data section, and the submission is capped at 256 instructions / 1024 data words / 20M cycles. Because the game gives no local way to try a policy — the sandbox has no cvm/cvmc/asm binary, confirmed by the agent's own find — the only feedback loop is push to the task branch and read the rating CI reports back.

Turn by turn

  • Read SPEC, design v1 (item_1-item_14): the agent read README.md and SPEC.md, checked for local tooling (none found), then wrote a first policy: material corrected by SEE for hanging pieces, a check bonus, a stalemate special case, mobility difference, an exposed-piece penalty, king-distance, centrality/rank terms and a symmetric PST for minor/major pieces. It counted instructions locally (40) before pushing.
  • v1 fails (item_15-16): git push returned a CI verdict: bot.cvm line 37: '4' is not a register — the agent had written DIV r6, r6, 4, an immediate where CVM requires a register operand. This is a SPEC-reading slip, the only outright mistake in the run.
  • v1 fixed, passes at 940 (item_17-19, seconds 427/444): the agent loaded 4 into r0 first and re-pushed; CI reported rating 940 out of a 0-1201 field. This banked a passing entry at just 8% of the 5400-second budget — a strong pacing outcome regardless of what followed.
  • v2, PST refinement, v3 reaches 1083 (item_20-36, seconds 607-1371): the agent made centralization/advance weights piece-dependent via a data table (985), then added symmetric PSTs generated and verified in Python for correctness before encoding (1083). This v3 became the reference baseline the agent returned to repeatedly.
  • v4 regresses to 1002, v5 regresses to 985 (item_37-58, seconds 1957/2349): a color-aware full PST (pawns and king included, torank/center terms dropped) underperformed v3, and a follow-up hybrid (v3's terms plus only a color-aware pawn PST) also underperformed. Both were correctly diagnosed by diffing against v3 and reverted with git checkout <v3 sha> -- bot.cvm rather than hand-editing forward, which is a clean way to avoid compounding an already-diagnosed regression.
  • Weight hill-climbing, 1092 up to 1179 (item_59 onward, seconds 2479-3668): from the 1083 baseline the agent ran single-parameter sweeps: castling bonus 20→50 (1092), mobility weight 6→5→7 (each tested and reverted), exposed-piece divisor 4→5 (reverted), and, most valuably, a new 'pawn near promotion' bonus on ranks 6-7, tuned 30→40→50→60→70 with 60 the peak (1179). Several further ideas — a graded (rank-scaled) version of the promotion bonus, a PLY-gated check bonus (small in the opening, larger later), a knight-on-the-6th-rank bonus mirroring the successful rook-on-7th term, a tempo-wasting-shuffle penalty, a stronger stalemate bonus, and a 5th-rank pawn bonus stacked on the promotion bonus — were each tried and reverted after regressing or landing neutral. This stretch is honest exploration but also fairly unfocused: several of these terms (e.g. PLY-gated check, knight-6th) had no stated reason to expect they'd help beyond pattern-matching the one term that had worked (rook/pawn on 7th), and each costs a full CI round trip to falsify.
  • Convergence and clean exit (item_161-168, seconds 3618-3691): the agent re-tested castle bonus 50 vs 60 once more with the rest of the config settled (60 confirmed best, 1179), ran a last local sanity check of jump-label targets (a self-authored regex script that produced false-positive 'MISSING LABEL' warnings on register operands, correctly dismissed since CI had already validated the assembly by executing it 540 times), then tagged and pushed release, which ends the run. Final elapsed time was 3691 of 5400 seconds (68%) — the agent chose to stop, it was not cut off.

Why it passed

Every attempt after the first fix passed verification (attempts in run.json shows one failure then 48 consecutive passes). The entry of record is the best-rated push, 1178.5 (reported as 1179), which sits close to the top of the field (max 1201) and far above the weakest opponent (0). The one and only defect in the whole run — the DIV immediate-operand error — was caught by the CI's own error message and fixed in the very next push, so it cost time (about 17 seconds of run time plus a push round-trip) but never risked the outcome.

Environment

Nothing in the harness, sandbox or verifier caused a problem. metrics shows 193 requests with 1 failed and 1 aborted (HTTP 499, a client-side disconnect visible in proxy.access.log), and proxy.error.log only shows benign nginx warnings about a duplicate Server header from the upstream. None of this altered the trajectory; the agent's own tool loop continued unaffected.

Assessment

This is a clean, agent-caused pass. The strategy (material + SEE + mobility + PST, iteratively weight-tuned) is a sound one-ply evaluation design for the CVM's constraints. Execution was disciplined about reverting regressions and keeping a known-good baseline, but wasteful in its later stages: without a local simulator, every hypothesis had to be validated by a live CI round trip, and the agent tried a number of low-conviction variants (PLY-gated bonuses, knight-6th, tempo penalties) that a moment's more reasoning about SEE/mobility interactions might have pruned before spending a push on them. It nonetheless banked a strong, near-ceiling rating well inside budget and ended the run on its own terms.
