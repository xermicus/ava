What happened

The workspace side of the environment was healthy: the harness's clone of the task repo succeeded cleanly —

So the sandbox, the proxy's git routing, and the bare repo serving the task were all fine. The failure is entirely on the LLM path.

Every model call failed

Two things are broken here, not one: the parity backend's model host (a self-hosted vLLM instance expected at host.docker.internal:18000, presumably standing in for deepseek-v4-flash to test parity against the vendor API) was simply not listening. And litellm's own fallback — which the error message shows was configured to catch exactly this, routing to openrouter/deepseek/deepseek-v4-flash-0731 — failed to engage ("No fallback model group found" despite one being listed right above it), so the gateway had no way to cover for the dead backend. The x-litellm-key-* ratelimit headers on both 500 responses confirm the litellm gateway itself was up and answering; it's specifically the upstream route and its fallback wiring that were broken.

The agent's harness (pi) auto-retried on this error on its own account, backing off 2s and then 4s (auto_retry_start attempt 1, then attempt 2, both carrying the identical error message). Its third attempt opened a turn_start and sent a third request, which the proxy logged as 499 — closed by the client before an answer arrived — right as the run ended. agent.log stops mid this third turn, and run.json's finished_seconds - started_seconds is exactly 34 seconds, against a 5400 second budget. monitor.json is still showing "turn":1,"elapsed_seconds":0", a snapshot from the very start of the run that never got to update — everything happened inside the first turn, before the monitor loop ticked forward once.
