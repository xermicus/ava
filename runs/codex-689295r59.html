chess-vm run analysis

What happened

The agent (codex harness, deepseek-v4-flash / deepseek-flash-parity route) was given the chess-vm task: write bot.cvm, a one-ply move-scoring policy in the CVM assembly language, verified by playing 20 games against each of 27 opponents and converting the result to an ELO-like rating.

It opened by reading README.md, task.md, and SPEC.md in the first two commands, then discovered there is no local assembler/verifier available (find / -iname '*cvm*' only found the workspace's own bot.cvm) — testing has to go through the CI. It immediately exploited the task's documented tar -c --exclude=.git . | curl -s --data-binary @- http://score:8080 shortcut, which runs the same verifier without recording an entry, to probe the stock bot first:

"bot.cvm has rating 316, the field ranges from 0 to 1201"

Strategy: coordinate ascent against a free oracle

From there the agent wrote a first heuristic (MATERIAL + (SEE-GAIN) + MOBILITY + OPPMOB + GIVESCHECK + MATEIN1 + EXPOSED + ISCASTLE + CENTER + TORANK + KINGDIST), which jumped the rating from 316 to 940 in one step. It then ran roughly 90 further probes (see the agent_message trail), each changing one term or one weight, testing it against score:8080, and either keeping it as the new baseline or reverting:

  • 958 → 965 → 977 → 978 from adding and tuning a development table and a PST, keeping only the changes that helped.
  • A genuine breakthrough: raising the KINGDIST weight from 3 to 15 lifted the rating from 982 to 1026 ("Big jump: KINGDIST 10 → 1014! ... KINGDIST 15 → 1026").
  • Further squeezing to 1031 (SAFE weight 20→40), 1033 (rook 7th-rank PST bonus), and 1034 (KINGDIST 15→16).
  • Numerous dead ends were tried and correctly reverted: phase-gated KINGDIST, ENEMYKINGDIST, OWNKINGDIST, HANGS penalty, doubled knight PST, capture-preference bonus, halved pawn PST, MATERIAL/2 — all logged as "hurt" and rolled back.

The agent kept named snapshots (/tmp/base1033.cvm, /tmp/base1034.cvm) and diffed the working file against them before every commit, which is why the search stayed coherent across ~90 single-variable trials instead of drifting.

Mistakes

Two small self-inflicted errors, both caught immediately by the verifier's fault reporting and fixed in the next turn:

  • bot.cvm line 4: '2' is not a register, the registers are r0 through r15 — the agent wrote MOD r10, r10, 2 when the ISA only allows register operands for MOD, not an immediate; it needed to load 2 into a register first.
  • It also referenced a SUBI mnemonic that doesn't exist in SPEC.md's instruction table and had to replace it with ADDI ..., -1.
  • Once, changing several PST weights simultaneously caused an unexplained regression (958→902) that forced a revert-and-retest-individually detour, costing a few probes but no real harm since it was caught immediately via the CI oracle.

None of these mistakes reached a recorded push — they were caught by the unrecorded score:8080 endpoint before anything was committed.

Why it passed

The task passed cleanly because the agent (1) understood and used the free-verification shortcut immediately, (2) ran a disciplined, revert-on-regression, one-variable-at-a-time search loop instead of guessing blindly, (3) banked a strong solution early and kept improving instead of stalling, and (4) stopped itself deliberately once returns diminished ("many recent experiments all hurt or were neutral") rather than burning the rest of the budget or risking a bad last-minute edit.
