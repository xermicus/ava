Overview

Game: chess-vm, one turn, task is bot.cvm, a move-scoring policy in a restricted assembly language (16 registers, no memory/stack, no search allowed, 256 instruction / 1024 data-word / 20M-cycle caps per decision). Every push is graded against a fixed field of 27 built-in opponents and reports a rating on 0–1201; there is no separate pass/fail threshold beyond the program executing without faulting, so the run was a "pass" from its very first push.

Run used only 6 turns (turn 1 plus loop iterations 2–6, agent.log), no compactions, and ended when the agent itself tagged and pushed release — the run never reached a forced last call.

Verification discipline

Every improvement claim was checked against the local, non-recorded score:8080 endpoint before being committed to the graded task branch; score.error.log contains 59 "passed" verifications against only 15 recorded pushes, confirming the agent tested roughly 4x more variants locally than it ever risked on the graded branch. This is exactly the workflow task.md invites ("CI without pushing... Same pipeline, not recorded") and it is why every recorded push was a genuine improvement — no regression ever reached score.log.

Minor issues

  • Two wasted pushes at the very start from CVM syntax errors (fixed immediately, no rating cost since a fault does not record an attempt at all — only score.error.log, not score.log, shows them).
  • The agent occasionally lost track of whether its working tree matched the last-pushed commit, needing to re-diff and restore v5p three separate times (turns 79–104), and left untracked scratch build files that it had to clean up more than once. This cost turns but never risked the graded submission.
