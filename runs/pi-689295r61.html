Task

chess-vm asks for bot.cvm, a move-scoring policy in a small assembly language with 16 registers, no memory or stack, and instruction/data/cycle limits. The engine runs the submission once per legal move and plays the highest-scoring move; a submission cannot search. Every push is rated against a fixed field of 27 opponents (ratings 0-1201), and the verifier both grades and reports the rating in the push reason, giving the agent a live signal it can optimize against.

This set the shape of the whole run: every hypothesis about a feature or weight had to be validated by a real push-and-wait cycle rather than a fast local loop, so each iteration cost real wall-clock minutes of the phase's budget.

First pass and the two register-operand failures

The agent pushed a first version quickly and banked a pass at 266s with rating 928 (score.log), immediately eliminating any risk of an empty run. It then iterated on positional and mobility terms, banking further passing entries through 488s at ratings in the 845-928 band as it tried different combinations.

At 699s a push failed: bot.cvm line 30: '1' is not a register, the registers are r0 through r15. The agent grepped the file (agent.log:7853-7887) and found the cause: sub r3, r3, 1 — the CVM's SUB instruction takes two register operands, with no immediate form (unlike ADDI/MULI, which do accept an immediate). It fixed that one instance and re-pushed, but the same new code block also contained mod r6, r5, 8, an identical class of mistake (MOD likewise requires two registers). That push failed at 727s: bot.cvm line 33: '8' is not a register. The agent had checked other sub call sites for the same problem but did not generalize the lesson to every instruction taking a literal where the ISA expects a register, costing a second avoidable CI round trip before the fix landed and the push at 748s passed with rating 988.

The tuning loop

From 748s onward the agent ran roughly 35 more pushes, each changing one feature or weight and reading the resulting rating: piece-square tables, mobility, an endgame king table switch, a check bonus, a castle bonus, then pawn-structure terms (passed pawns, doubled pawns, an isolated-pawn penalty). It explicitly tested and reverted regressions — e.g. an ENEMYKINGDIST attack-proximity term that had cost about 83 points in an earlier balance was tried again at a milder weight late in the run and reverted again (agent.log tail, commit 585e257 revert enemykingdist (1080 best)). The rating climbed unevenly (988 → 1037 → 1080 by 2534s) as the agent converged on a balance where positional/pawn-structure terms helped and aggressive king-attack terms hurt.

Deciding to stop

By roughly 2326s the rating had plateaued in the 1045-1080 band across repeated confirmations. The agent's own commentary (agent.log tail) walks through several more candidate experiments (castle 110, center weight, connected-pawn bonus, enemy-king-distance at weight 1) and talks itself out of most of them as low expected value given ~47-minute CI turnaround per experiment relative to the diminishing gains observed. It ran one final low-risk experiment (castle bonus 110, same 1080 rating as 100), reverted an enemy-king-distance re-test, verified the committed file was complete and within the 256-instruction/1024-word limits, and tagged release at 2947s — just over half of the 5400s budget — ending the run deliberately rather than exhausting the clock.
