Task

chess-vm asks for bot.cvm, a static move-scoring policy (no search) written in the CVM assembly SPEC.md defines. A verifier plays it in a round-robin against 27 fixed-strategy opponents (random, greedy, pacifist, sensei, tactical, etc.) and reports a rating on a 0-1201 scale.

What the agent did

Recon (first ~15 tool calls). Read README.md, task.md, SPEC.md, the starter bot.cvm (a 3-instruction stub scoring 0 for every move), and .gitignore. Probed the environment for a CVM toolchain (which cvm cvmasm..., none found) and for network topology (cat /etc/hosts, getent hosts git score). It found a score host reachable from inside the sandbox.

Discovering the free test loop. It first tried curl --data-binary @bot.cvm http://score:8080 and got HTTP 400 the body is not a tar archive. It corrected to tar -c --exclude=.git . | curl ... http://score:8080 and got back a full verdict JSON, including a rating, without that push touching git. This is the score host the book describes as verifying "a posted tar without recording it" — distinct from git push origin task, where "every push to the task branch is verified on the spot and the entry of every passing push is kept." The proxy log confirms the split: 48 requests to score (self-test) vs 11 to git (real pushes), while only 4 of those git pushes became recorded attempts.

First real solution. Wrote a one-ply static evaluator combining SEE (static exchange evaluation), promotion value, mate-in-1 detection, check bonus, mobility differential, center control, castling bonus, exposure penalty, and king-tropism terms. Self-tested it (935.7, versus 316 for the starter) before committing: "935/1201 is a strong first result (baseline random-mover scored 316). Let's commit and push this as our first submission, then keep iterating." This became the first attempt at 384s.

Iterative tuning loop. For the rest of the run the agent repeated: edit one term's weight or add/remove a term → tar | curl score:8080 → compare to /tmp/best_rating.txt → cp the file back from /tmp/best.cvm if it regressed, or overwrite /tmp/best.cvm if it improved. Examples: halving the EXPOSED penalty (934.7 → 959.5), boosting mobility weight from 2 to 4 (→982.3, then testing 8 and 5 which were worse and reverting), zeroing OWNKINGDIST (→1015.3, kept) and testing its negative sign (997, reverted), and testing GIVESCHECK at 15 vs 30 (identical 1015.25, confirming the term was non-binding at that magnitude). It periodically pushed the running best to the graded branch at 3807s (1029.3) and 4237s (1092.3).

The one real mistake. While halving the EXPOSED term, an edit produced DIV r2, r2, 2 — an immediate literal where the ISA requires a register operand. The self-test immediately returned bot.cvm line 44: '2' is not a register, the registers are r0 through r15. The agent fixed it in the very next turn by loading the constant into r5 (LDI r5, 2) and using DIV r2, r2, r5, then re-tested successfully (959.5). Because this was caught by the self-test loop, it never reached a graded push and cost only one wasted turn.

Best single improvement. Adding a flat penalty for non-castling king moves (MOVEDPIECE check) took the rating from 1029.3 to 1048.8, then tuning the penalty magnitude (30→60→100→180→130→110) pushed it to 1092.3, pushed at 4237s. A final retune of the enemy-king tropism weight (2→1) reached 1097.8 (effectively 1098), pushed at 4915s — the last graded attempt of the run.

Tail of the run. After 4915s the agent kept experimenting (a phase-aware EXPOSED refinement scored 997, worse, reverted; a queen-move-penalty idea was proposed but not implemented) without finding further improvement. The session log shows a mid-run reinitialization (a second system/init event with the same session id, not counted as a compaction in run.json) right as the agent was about to try the queen-move idea; the log ends with a clean git status --short (no diff) against commit 382c534 — the same commit that produced the 1097.8 rating — confirming the final graded state matches the agent's actual best and nothing was lost.

Why it passed

All four graded pushes passed (score.log/run.json agree), rating climbed monotonically across banked checkpoints (935 → 1029 → 1092 → 1098) on a field ranging 0-1201, and the last bank landed at 4915s of a 5400s budget — comfortably before the deadline, with the trailing ~480s spent on unsuccessful exploration rather than sitting on unbanked work. There is no never_wrote, unbanked, hung_tool, wrong_place, wrong_solution or environment failure here; this is a clean pass driven by the agent's own methodology.
