What happened

The task: write bot.cvm, a one-ply chess move-scoring policy in the CVM assembly language (chess-vm game), verified by playing 20 games against each of 27 opponents and reporting an ELO-style rating. The run had a 3600s budget; the agent finished (tagged release) at 1165s, using roughly 43% of the budget across 131 model requests.

Strategy

The agent read README.md, task.md and SPEC.md first, then wrote a single evaluation function combining MATERIAL + SEE (material and static exchange), a mobility differential (MOBILITY - OPPMOB), an EXPOSED/HANGS safety penalty, small bonuses for checks/castling/promotion/centrality, a pawn-advance term, an early-king-safety penalty, and a MATEIN1 short-circuit. From there it ran a manual coordinate-descent hyperparameter search: hold everything fixed, sweep one constant (check bonus, mobility weight, center weight, king-safety weight, pawn-advance weight, exposed divisor, defender bonus…), keep the winner, move to the next term.

Verification discipline

Before every git push the agent ran the exact CI pipeline locally: tar -c --exclude=.git . | curl ... http://score:8080, which grades without recording a submission. This caught two assembler bugs before the first real push:

  • bot.cvm line 25: '8' is not a register — it had written DIV r1, r1, 8 where the ISA requires a register operand, not an immediate.
  • bot.cvm line 59: unknown instruction 'JNE' — CVM has no JNE; the agent replaced it with SUB+JZ.

Only after both were fixed and the local grader reported 906 did it commit and push (Add material and safety move policy, banked at 210s, 5.8% of the budget). It repeated this pattern for every subsequent push, three more times: 971 at 481s, 1002 at 591s, 1031 at 1165s — always testing locally, always pushing on a confirmed local win, never leaving a positive delta unbanked.

What went well

  • Fast first bank: a passing solution was on the branch by 210s, so nothing was ever at risk of being lost to a timeout.
  • The tune loop was disciplined: one variable at a time, immediate measurement, revert on regression, and every kept change was pushed. No wasted or orphaned improvement — all four local peaks (906, 971, 1002, 1031) were the ones actually recorded by score.log.
  • The agent correctly diagnosed several dead ends instead of just accepting numbers at face value: it noticed the OPPMOB-only and MOBILITY-only variants both regressed sharply (839–887) "confirming our own mobility matters most," it tested whether the winning DEFENDERS bonus was driven by captures, king moves, or pawn moves specifically (isolating each with JNZ/JZ guards) before concluding it should apply to all pieces uninterrupted.
  • It recognized the search had plateaued (repeated regressions on KINGDIST, MOVECOUNT, piece-specific defense) and terminated cleanly with git tag release && git push origin release at ~1165s rather than burning the remaining ~2400s of budget on diminishing returns — exactly the exit condition described in the task hints.

Mistakes the agent made

  • A python3 heredoc inserted literal + diff markers into bot.cvm (item 44): sed/patch text carried over + prefixes from a diff-style string, giving bot.cvm line 30: unknown instruction '+'. Caught immediately by the local grader and fixed with sed -i 's/^+//', but it cost an extra local round-trip.
  • A shell-quoting bug (item 48) caused a for weight in ... loop's heredoc to not receive the $weight variable at all (it wasn't exported to the python subshell), so five consecutive "DEF"/"SAFE" experiments silently re-graded the same stale candidate and reported an identical 911 rating each time. The agent's own commentary ("Surprisingly... both removing the bonus and weight 6 beat 971") shows it initially treated these repeated noise artifacts as real experimental signal before catching the bug in the next turn and rerunning correctly (item 50), which is when the real 1031-rating discovery (DEFENDERS bonus of 2) actually surfaced.
  • The tuning method is single-shot coordinate descent against a fixed-seed evaluation (20 games/opponent, deterministic seeds). The agent explicitly flagged this itself — "the fixed-game noise is substantial" (item 28) — yet kept making one-parameter-at-a-time keep/discard decisions off single measurements with deltas as small as 5-15 rating points, some of which move in the direction that later analysis of interactions (capture-only vs king-only vs pawn-only variants) may not have fully accounted for.

Environment

No environment problems: no proxy errors, no hung tool calls, no truncated or aborted requests (only 1 of 131 requests recorded as "failed", consistent with a normal transient and not a run-ending issue), and the harness completed normally. The one warning ("Model metadata for openrouter/z-ai/glm-5.3 not found... defaulting to fallback metadata") did not visibly degrade the run.

Decisive factor

Testing every candidate against the local, unrecorded score:8080 endpoint before ever pushing. This is what let the agent iterate freely (dozens of local grades) while only committing to the graded branch four times, each an unambiguous improvement, with the first bank at 210s. Nothing about the final 1031 rating depended on luck at push time — every pushed version had already been locally measured with the exact same seeds the CI would apply.
