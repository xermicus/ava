What the agent did

The task was chess-vm: write bot.cvm, a one-ply chess move-scoring policy in a small register assembly language, graded by playing 20 games against each of 27 built-in opponents and reporting an ELO-style rating (field spans 0 to 1201).

The agent read README.md, task.md and SPEC.md, found the starter stub (ldi r0,0 / score r0 / halt), and immediately discovered a key mechanic of the sandbox: http://score:8080 runs the real verifier against a posted tar of the workspace but, per the book (architecture.md), "verifies a posted tar without recording it" — unlike a git push origin task, which is graded and banked. The agent used this correctly as a zero-risk test harness for the rest of the run: 244 requests to score, against 5 to git (the initial clone/branch bookkeeping and exactly one final push).

Why it passed, and how close it came to not banking anything

The push that mattered — the only one that counted — was the very last tool call the agent made before its budget ran out. Every other check was to the unrecorded score endpoint, correct for validating a candidate cheaply but useless for banking an entry: run.json's attempts array and score.log both contain exactly one line, at 3504s. Up to that point the agent held zero banked entries despite already having a rating-894 policy 83 seconds in and steadily improving ones after. If the final turn's regeneration had failed outright instead of falling back cleanly (e.g. if the agent had mis-transcribed the weights, or the git push itself had hit a transient failure with no time left to retry), the entire 3600-second run — and its genuine rating-1024.6 result — would have scored nothing.

Where the budget went

Of 3600 seconds, roughly 900 (25%) were spent on a single random-search call that returned nothing because the agent didn't first check how expensive a fresh (uncached) evaluation was. That time, recovered, would easily have covered an early safety-net push plus another full round of coordinate descent or exploration of the hanging-piece idea sooner — the idea that ultimately drove the rating from 984 to 1024.6 and only surfaced with roughly 400 seconds left in the run.

Verdict

The agent's technical execution — the scoring-term engineering, the ablation-then-coordinate-descent search strategy, and the late structural insight about hanging pieces — was sound and produced a genuinely good result (rating 1024.6 of a 0-1201 field). But its process risk was self-inflicted on two counts: an unbounded, unmeasured random search that ate a quarter of the run, and a policy of never touching the graded git branch until literally forced to in the final turn. The pass is real, but it was banked with no margin and no fallback.
