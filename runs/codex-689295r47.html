Task and setup

chess-vm asks for bot.cvm, a one-ply move-scoring policy in the CVM assembly language (no .search, 256 instructions / 1024 data words / 20M cycles per decision). Every push is scored against a fixed field of 27 opponents and reports a rating; points() never executes anything, so passing pushes are ranked purely on the rating recorded at verification time, and the entry of record is the best rated push kept.

What the agent did

The agent (shanelle, codex harness on deepseek-v4-flash/deepseek-flash-parity) read SPEC.md, found no local assembler, and wrote a Python generator (gen.py) that emits bot.cvm from a JSON config of feature weights: mate-in-one, SEE (static exchange eval), a hang penalty, a check bonus, promotion value, mobility differential, exposed-piece penalty, a safe-destination bonus, a castling bonus, distance to the enemy king, and mirrored piece-square tables for the moved piece's from/to squares.

Two generator bugs surfaced immediately on the first local check: the assembler has no SUBI (only ADDI), and MOD needs a register operand, not an immediate. Both were fixed before any push.

The key move was discovering http://score:8080, the unrecorded scoring endpoint the book describes (benchmarks.md: "A tar posted to http://score:8080 is verified the same way and not recorded"). The agent used this 19 times as a free CI loop, running weight sweeps and recording the rating of each variant without spending a real push:

"Let me build a parameterized generator so I can experiment with feature weights via the fast non-recorded CI."

Through this loop it found, in order: mobility weight 3 (1054 local), enemy-king-distance (EK) weight 6 (1000), then progressively higher EK weights — EK15 → 1143, EK16 → 1154 — check bonus retuned to 10 at EK16 → 1167, safe_b=0 → 1169, and finally a GIVESCHECK × ISCAPTURE interaction term (check_capture) at weight 10 → 1178.5. It also tried and discarded several ideas that tested flat or worse locally: alternate piece-square tables, an endgame king-centralization term via board scan, SEE scaling, a doubled-pawn penalty, a raw material-gain (MVV-LVA-style) bonus, and phase-aware (material-dependent) reduction of the EK weight, the last of which "hurts badly."

Assessment

This is disciplined, well-instrumented tuning. Rather than guessing at weights or spending real pushes to probe every idea (each real push both takes wall-clock and permanently records a worse rating if it fails to improve), the agent exploited the unrecorded scoring endpoint to get near-free feedback, converging on a materially better evaluator (951 → 1179, near the field's max of 1201) with only four real pushes. It correctly recognized when marginal tuning had plateaued (several late-stage ideas — doubled pawns, phase- aware weights, raw material-gain bonus — all failed to help) and stopped rather than continuing to churn. Ending the run early via release was a reasonable call given diminishing returns, though it left a substantial time budget on the table that more exhaustive search (e.g. trying entirely different feature combinations, not just weight sweeps around one local optimum) might have used productively. There is no environment failure and no agent-caused defect; the outcome is a clean pass driven entirely by sound agent strategy.
