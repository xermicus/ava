Task and approach

The game is chess-vm: submit bot.cvm, a move-scoring policy in a restricted CVM assembly (16 registers, no memory writes, no stack, no .search, capped at 256 instructions / 1024 data words / 20M cycles per decision) that scores a single candidate move; the engine plays the highest-scoring legal move. Since search is impossible, the only lever is a better static evaluator of the after-move position.

The agent opened by reading the task and the CVM spec, then measured a baseline: a trivial random-ish bot rated 316 against the field of 27 opponents (0–1201). It reasoned correctly about the constraint shape early: "I have huge cycle headroom ... so I'll build a real positional evaluation" — cycles were never the bottleneck (final builds used ~2000 of 20,000,000 per move), instructions (256) were.

Building and debugging the tooling

Before writing v3 the agent noted it had "no local assembler to catch mistakes (a fault = automatic fail)" and built cvmcheck.py, a local interpreter that validates instruction/data-word counts, label resolution, and LD bounds, with chess instructions stubbed to plausible constants so control flow could be exercised without the real engine. This was the single highest-leverage decision in the run: from that point on, every candidate edit was validated locally before spending a CI round-trip, and the interpreter's own bugs (e.g. jump instructions read the register operand instead of the label operand, and NEG assumed two operands when the real ISA and the agent's own bot used a valid one-operand form) were caught and fixed rather than silently producing false confidence for very long.

Iteration and tuning

The trajectory across pushes (rating in parentheses) was: v1→988 (PST + material), v2→1071 (hanging pieces, passed pawns, king safety), v3 attempts a refactor and briefly regresses to 978 because a moved data table kept a stale offset — the agent found this by diffing the miscompiled build against the committed 1102 version rather than assuming the new feature itself was bad. From there it iterated methodically: SAFE-move bonus (+8 → 1111), mobility weight sweep (2→3 gave the single biggest jump, 1111→1181), check/castle/SAFE weight sweeps (→1200, then past the field's nominal ceiling to 1203, prompting it to note explicitly that the reported rating can exceed the top opponent's raw rating), then PST-table tuning (pawn ranks 4/5/6/7, knight edges, bishop diagonal, rook 7th rank, endgame king centralization) taking it to 1226→1232→1240, and a final round of instruction-budget housekeeping (dropping dead promo-nudge code, re-probing SAFE weight to 16) landing at 1243.2 (v18).

Each experiment was one change at a time, confirmed with cvmcheck.py then pushed, and the agent tracked when it hit "saturation" (repeated probes returning the same or worse rating) as the signal to move to a different knob (scalar weight → PST shape → structural instruction reallocation) rather than continuing to grind a dead lever.

Pacing and closing

The first passing push landed at 1982 seconds — over half of the 3600-second budget spent reaching a working, committed baseline (988→1102 through several local debugging cycles) before the first push. From there the remaining ~1250 seconds were used efficiently: 16 more passing pushes refining the evaluator, each backed by a local sanity check. At roughly 3234 seconds the agent judged further tuning was noise-level ("±3 noise around 1243"), verified the working tree matched its best committed version, ran a final confirmation push, and voluntarily tagged and pushed release — ending the run itself with about 366 seconds of budget still available (monitor.json shows last_call: false, turn: 1, confirming this was a self-initiated stop within the single ordinary turn, not a last-call scramble).

Outcome

The run passed on its very first attempt and improved on every metric afterward: 17 of 17 attempts recorded in run.json passed, the rating rose monotonically with only the one transient regression (caught and fixed before it was ever pushed as a worse regression — the 978 result never displaced the 1102 base), and the final entry (1243) beat every one of the 27 built-in opponents, including the four-ply search bot. There is no environment issue anywhere in the logs: no failed/aborted requests beyond one incidental proxy abort, no hung tools, no infrastructure failure — the outcome was earned entirely by the agent's disciplined build-test-tune loop.
