What happened

The task was to write bot.cvm, a chess move-scoring policy in the CVM assembly language for the chess-vm game (single-turn, no search allowed, scored by ELO rating against a fixed field of 27 opponents).

Early exploration (0–280s)

The agent first tested the default random bot to establish a baseline (rating 316) and confirm the local scoring pipeline worked, then wrote a v1 policy combining material, mobility, mate-in-1, and tactical (SEE/EXPOSED) terms, jumping straight to 882.

Harness and systematic tuning (280–2600s)

A v2 attempt regressed to 699 (SUB doesn't take an immediate — 'SUB takes only registers. Using ADDI instead.'), so the agent reverted to v1 and built a proper test harness:

cp "$1" /home/agent/workspace/bot.cvm
cd /home/agent/workspace
out=$(tar -c --exclude=.git . | curl -s --data-binary @- http://score:8080)

This posts straight to the local score sidecar — the same verifier code the real push uses — giving a ~3s feedback loop. It then generated batches of variants (e.g. b/m8_mo5_c50_e-8_k0.cvm) and ran them all via a runall.sh sweep, sorting by rating to find good weight combinations (mat=8, mob=5, chk=50, exp=-8 as a base, best variant 937 in that sweep). It hit one bug along the way — a naive replace('H', ...) placeholder substitution also mangled the literal HANGS mnemonic into 100ANGS, breaking a whole batch of combo variants with unknown instruction '100ANGS' — caught immediately from the verifier's error message and fixed. Continued tuning added OWNKINGDIST, HANGS, and KINGDIST terms, reaching 952.5 by ~2577s. At 2589s it found the workspace file didn't match what it had just written and rewrote it, then confirmed 953 and pushed at 2601s — the first passing push, bot.cvm has rating 953, the field ranges from 0 to 1201, comfortably inside the 3600s budget.

Second pass and the self-inflicted bug (2600–3600s)

The agent kept exploring after banking the pass. It found that adding a LIGHTCOUNT term (piece-square lightness) pushed the rating to 968 around 3424s. Right after, it hit the same symptom as before: 'The file reverted to an older version (something may have restored it). Let me check git and what was committed' and then 'A background process overwrote bot.cvm with an old variant (likely a leftover test.sh run).' This diagnosis, while directionally right, missed the actual mechanism: test.sh itself does cp "$1" /home/agent/workspace/bot.cvm on every invocation, so any later test run — including ones testing older/worse candidate variants for comparison — silently clobbers whatever the agent had just hand-written into the live submission file. There was no external background process; it was a deterministic side effect of the agent's own harness design (the test script mutates the exact file it later commits and pushes), and the agent never identified this root cause even after investigating.

This collided badly with timing: the clobber was rediscovered at 3431s, only ~170s before the hard deadline, and the harness's original variant files under /tmp were already gone ('The /tmp variants are gone, but I have the best config (967.94 = base + LIGHTCOUNT2) in context.'). The agent reconstructed the winning policy from its own conversation context, verified locally ('Confirmed 968 locally.'), and pushed. That push landed during the run's last-call turn (a fresh harness invocation triggered because the main turn's clock ran out) at 3579s of the 3600s budget — 21 seconds of margin.

Outcome

Both pushes passed: 953 at 2601s and 968 at 3572s (recorded). Because the first pass was banked at 72% of the budget, the run's success never actually depended on the last-call recovery — but the recovery itself was only needed because of the agent's own tooling bug, and it left essentially no margin for error on the final, best-scoring entry.

Judgment

The agent's core method — building a local oracle that mirrors the real verifier and grid-searching weights against it — was sound and is why the score climbed steadily from 316 to 968 (a field of 0–1201). The mistake was entirely of its own making: a test script that overwrites the live submission file as a side effect, and a failure to trace the resulting corruption back to that script even after two occurrences. That cost time and turned what should have been a comfortable final push into a last-call scramble.
