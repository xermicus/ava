What happened

The task was chess-vm: write bot.cvm, a move-scoring policy in CVM assembly, run once per legal move with no search, evaluated by playing 20 games against each of 27 built-in opponents and rated on the 0-1201 scale the field spans.

Build-test-fix loop, protected by the untracked score endpoint

The book documents two ways a submission reaches the verifier: pushing the task branch to git, which records a graded attempt, and posting a tar to score, which verifies but records nothing (benchmarks.md: "The score host on the same socket verifies a posted tar without recording it."). The agent used the second path as a private test loop. proxy.access.log shows five score / POSTs (08:01:10 405, 08:01:15 200, 08:04:40 200, 08:05:00 200, 08:05:15 200) against only two git-receive-pack pushes (08:05:51 and 08:08:19), plus the release tag push at 08:08:23. Every real push had already been dry-run through score first.

That loop caught real mistakes cheaply. The scorer log records:

[2026-09-25T08:04:39Z INFO  ava_game] bot.cvm line 37: unknown instruction 'SUBI'
[2026-09-25T08:04:39Z INFO  ava_scorer::score] the chess-vm submission of turn 0 failed
[2026-09-25T08:05:00Z INFO  ava_game] bot.cvm line 53: '12' is not a register, the registers are r0 through r15
[2026-09-25T08:05:00Z INFO  ava_scorer::score] the chess-vm submission of turn 0 failed

matching the agent's own narration: "No SUBI in this machine — only ADDI. Negating the immediates:" followed a message later by "My sed mangled the file. Rewriting cleanly..." and "Line 53: DIV r3, r3, 12 — DIV takes a register, not an immediate... That sed hack is wrong... That second edit is nonsense — DIV r12, r12, r12 gives 1." These are self-inflicted errors from writing the ISA from memory and patching with sed instead of checking SPEC.md first, but because they were caught against the untracked score endpoint, none of them became a failed graded attempt — score.log and run.json show only two attempts, both passing.

Three versions, rising rating

  1. A minimal 3-instruction placeholder passed with rating 316 (untracked, via score, 08:01:15): "random 6 wins 8 draws 6 losses ... bot.cvm has rating 316".
  2. A 119/121-instruction one-ply heuristic, fixed up after the SUBI/DIV mistakes, reached rating 752 and was pushed for real at 543s ("752 rating now. Let me commit this checkpoint, then upgrade...").
  3. A 120-instruction, 592-data-word full piece-square-table evaluation over a 64-square scan reached rating 1011 and was pushed at 690s ("1011 — big jump. Recording it.").

The scorer's per-opponent breakdown for the final version shows it beating nearly every opponent with 17-20 wins out of 20, losing only to a handful of the strongest search-based opponents (steady, sensei, positional, composite), which is consistent with a fast, cycle-cheap evaluation heuristic doing well against most of the field but not the deepest searchers — expected, since submissions cannot use .search.

Stopping well short of the budget

run.json gives limit_seconds: 3600, but started_seconds to finished_seconds is only 698 seconds. Immediately after banking the 1011-rated push, the agent wrote: "1011 recorded. Now refinements. Ideas worth testing (each cheap to add):" — then, instead of trying any of them, it ran an uninformative curl against score:8080/health and /status (both 405, telling it nothing: "post a tar archive of the tree to score"), and one tool call later ran git tag release && git push origin release, which ends the run on the spot (benchmarks.md: "The run ends when the time is up, when the agent pushes a release tag, or when the harness exits."). No further refinement was attempted. This left roughly 2900 of 3600 seconds (about 80% of the budget) unused, with the agent's own stated next steps abandoned rather than tried.

Environment

Nothing in the sidecar logs points to a harness, sandbox, or backend problem. The nginx warnings ("upstream sent duplicate header line", "js periodic ava.publish... killing previous instance") are routine proxy chatter, not failures reaching the agent. The one aborted (499) LLM request and the 405s on /health//status are artifacts of the agent's own probing and of the run ending right after the release tag, not an environment fault.

Verdict

This is a clean pass with real, measured improvement (316 → 752 → 1011) and disciplined use of the untracked score endpoint to avoid spending graded attempts on debugging. The only agent-caused blemish is tactical: writing CVM instructions from memory rather than the spec caused two avoidable failed dry-runs, and the run ended by choice at under 20% of the time budget, with concrete refinement ideas named and then dropped instead of tried.
