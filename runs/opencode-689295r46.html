Chess-VM run analysis

Task and setup

bot.cvm is a one-ply move-scoring policy in the CVM assembly language, judged by the ELO rating it achieves over 20 games against each of 27 built-in opponents (field spans 0-1201). Every push is graded on the spot; the task README explicitly offers a free, unrecorded check via tar -c --exclude=.git . | curl -s --data-binary @- http://score:8080, which plays the same 540 games without keeping the result.

What the agent did

  1. Read README.md, task.md and SPEC.md in the first few tool calls, correctly identifying the machine model (16 registers, no memory, chess instructions with their cycle costs).
  2. Immediately tested the stock bot.cvm (scores every move equally) through the unrecorded endpoint: rating 316.
  3. Wrote a first real policy combining material, SEE/GAIN, mobility, checks and mate detection: rating jumped to 943 within minutes.
  4. Iterated on weights and features through the unrecorded endpoint 23 times total, catching and fixing two assembler-level bugs along the way ("2 is not a register", "r4 is neither a number nor a label"), climbing through 969 → 991 → 1040 → 1047 → 1048.8 → 1052 → 1060.5 (named "dev20" in its own commit messages, adding a ply-gated development bonus).
  5. Once at rating 1060.5, it pushed to the task branch: git checkout bot.cvm && git push origin task → remote: pipeline: {"seconds": 2019, "passed": true, "reason": "bot.cvm has rating 1061, the field ranges from 0 to 1201", "rating": 1060.5289890430522}. This is the run's only recorded attempt (score.log has exactly one line, run.json has exactly one entry in attempts), and it passed on the first and only try, 2019 of the 5400-second budget in (~37%).
  6. It kept working after the push: an explicit feature ablation study ("Removing mob → 834 (critical)", "Removing exposed → 870 (critical)", "Removing okd → 1054 (small but positive)", etc.), a hill-climbing/random search over weight combinations ("none of the 40 random combos beat it"), and several structural experiments (non-linear SEE, material-conditional captures — which it caught mid-implementation had a JLE-against-the-accumulator bug and reverted — rook-on-7th bonus, a flat promotion bonus). Every one of these scored at or below 1060.5, and the agent correctly reverted the working tree to the committed 1060.5 version each time rather than let a worse variant leak into a commit.
  7. A second git push origin task at 15:06:36 reported "Everything up-to-date" — confirming no further commits had been made since the pass.

The stall

proxy.access.log shows an unbroken stream of LLM and score requests from run start through 15:12:26, then a single row: 2026-09-09T15:54:40+00:00 llm.substrate.dev /v1/messages 200 2533.435 (note the empty completed field, versus "OK" on every other row). This matches the run's one aborted_requests in run.json's metrics. agent.log corroborates: the last text/tool event of the working turn is at 1788966748876 (≈15:12:29), and nothing is logged again until 1788969285022 (≈15:54:45), a gap of 2536 seconds — the turn was blocked on this single request for essentially its entire remaining budget, and no other tool call in the log has a duration anywhere close to this (the longest ordinary tool call is 10.4 seconds), so this is a backend-side stall, not a runaway tool the agent itself triggered.

monitor.json's final snapshot shows "turn":2,"last_call":true, confirming the run had already moved to its second (and last) turn by the time it was captured. The last call turn (run=638940d1) starts right after the stall clears, does a git checkout bot.cvm && git status --short && git log --oneline -3 && git push origin task, finds the tree already matches the pushed dev20 commit, and reports "Everything up-to-date" — it changed nothing, because there was nothing left to bank.

Why it passed

The pass was never in doubt once banked: the agent used the unrecorded endpoint disciplined as a private test harness, so the one push it made was already verified to work. The final policy (MATERIAL base, SEE-GAIN exchange term, 8×(MOBILITY-OPPMOB), 40×GIVESCHECK, 100000×MATEIN1, -EXPOSED/2, -200×HANGS, -7×ENEMYKINGDIST, -OWNKINGDIST/4, 12×ISCAPTURE, a ply-gated development bonus) is a reasonable one-ply evaluation and reached rating 1060.5 against a field topping out at 1201 (a 4-ply searcher).

What could have gone wrong

Nothing did, but the margin was smaller than the final score suggests: had the 42-minute stall hit during the first 34 minutes instead of after, the agent might never have reached a passing configuration at all before the clock ran out, since the whole recorded history of this run is a single push. The task's own advice ("Keep improving the solution and commit + push subsequent submissions after the first passing one") was followed in spirit (constant iteration) but not in the letter that matters for scoring — no second push was ever made, so the entry of record is the same 1060.5 attempt from 34 minutes in; all of the post-pass work (ablation, hill-climbing, structural experiments) failed to find anything worth re-pushing, which is a legitimate finding (a validated local optimum) rather than neglect.
